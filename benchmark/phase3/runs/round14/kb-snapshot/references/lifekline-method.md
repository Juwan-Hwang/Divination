# lifekline 方法提炼与我们的改进路线（AI 八字 K 线应用解剖）

> 定位：lifekline 是把八字一生的逐年运势画成 K 线图的 AI 应用。本篇只提炼其**方法与提示词结构**供研究对照——两仓均无 LICENSE（默认版权），**不直接复制其代码**；结论来源：主会话 gh api 实查（2026-10-29）+ 本地克隆逐项复核（blob SHA、关键字符串均已验）。

## 二、方法提炼（它的核心资产到底是什么）
1. **核心资产 = 一段系统提示词 + 结构化 JSON 输出协议**：constants.ts 中的 BAZI_SYSTEM_INSTRUCTION 要求模型按 1–100 虚岁**逐年**输出 open/close/high/low/score/reason（K 线四值+评分+批断），并给总评与性格、事业、财富、婚姻、健康、六亲多维评分。K 线可视化只是呈现层，真正的「方法」是提示词+JSON 协议。
2. **它没有排盘引擎**：四柱、第一步大运、起运年龄全部靠**用户手填**；代码里唯一真实命理规则是大运顺逆判定（年干阳+男 / 阴+女顺行，services/geminiService.ts 的 getStemPolarity，本机已验其存在）。其余「命理」全部由大模型凭语料即兴生成，无任何可验证的计算。
3. **两版提示词差异（本机逐字复核）**：
   - Harry 版：每年 reason 要求**约 100 字详批**（含具体吉凶事件预测、神煞分析、应对建议）。
   - curionox 版：reason 收紧为 **20–30 字**，新增币圈/风水维度，且明文要求**「评分必须明显波动、禁止平滑直线」**（原文「禁止输出平滑直线」已验）。
4. **判断**：其「准」的观感很大程度来自**强波动提示词强迫模型编出起伏** + 大模型命理语料的套路化输出，没有可复核的排盘与规则链。逐年 score 本质是文本生成，不是计算结果。

## 三、剔除项（与本库筛选纪律对齐）
- 「禁止平滑、强行制造波动」类为好看而编数据的提示词手法——**暂不采用**（MANIFEST 暂不采用清单）：运势曲线可以平淡，分数必须由规则算出，不许为视觉效果注水。
- 「用户手填四柱+模型全编」的工作流不入本库方法：本库排盘一律由历算库计算并交叉核对（calibration.md）。

## 四、我们的改进方向（保留长处、补掉短处）
lifekline 值得学的只有两点：**逐年结构化输出**与**可视化呈现**。改进路线：
1. **计算层先行**：用 lunar-python/sxtwl 算准四柱、大运、起运与逐年流年干支（约定按 calibration.md 默认表），结果落成结构化数据（JSON），模型不得改动。
2. **规则层给依据**：逐年按流年干支与命局/大运的冲合刑害、十神到位、调候得失、神煞（只用有文本依据者）生成**依据清单**（每条带规则出处），score 由依据加权得出，reason 只能复述依据链——先有据、后成文。
3. **呈现层沿用其长处**：K 线（open/close/high/low 由 score 与当年冲合强度映射，映射规则写死在代码里并公开）、多维评分、逐年批断——但每根 K 线可点开看依据，接受 benchmark 式复核。
4. **回归校准**：成例命例（待《滴天髓阐微》等全文到位）进 benchmark，与大师断法对齐后再谈「准」。
