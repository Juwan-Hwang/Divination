# Phase 3 · 六爻输入质量核查试点 预注册（input-audit pilot）

立于 2026-10-30，主持角落盘提交后生效；本文件所定规则、样本与门槛在本试点内不得更改，变更只能另立新预注册并注明理由。

## 0. 背景与立项依据

- 平台 (c)（六爻 dev8 子集配对差 ≥ −1.93）是当前唯一未立的平台判据：R31 读数 −1.955（n＝246，SE 0.131），以 0.025 落线（R31 定稿维持、不复议）。
- 六爻方法侧穷尽层（取用程序、应期机制空间、方向四路合参、双程独立复核、执行层格式强制、条文决定式化）不得换名重立（PROTOCOL 追加登记 2026-10-30、STAGE-SUMMARY-14 §3）。本试点属**数据侧**，与方法侧无关。
- 既有输入工作均为诊断驱动的逐例补录（R26 诊断 C 类「输入缺陷」占深败 68 例的 19.2%；inputs9 补 47 例、inputs10 切换 44 例入 inputs-dev10），从未对 (c) 子集做过**普查级机械一致性核查**：卦面字段（纳甲地支、六亲、世应、变卦、动爻标记）彼此由确定规则互相决定，转录错误可被机械检出而不必先读原书。此即本试点的核查对象。
- 六壬侧：条目效力悬置（STAGE-SUMMARY-14 §3.1），本试点不涉六壬、不立六壬项。
- trigger 三布尔定义债：本试点不处理、不搭车（照旧挂账，单独立项才动）。

## 1. 假设

**H-IA**：`inputs-dev10` 中 (c) 子集（n＝246，口径照 R31 analyze：host-meta tradition＝liuyao ∧ 见于 master-baseline-dev8）的六爻案例卡，其卦面字段存在可机械检出的内部不一致；其中一部分系相对源本的转录错误（可纠正），其规模足以使「全量核查＋纠正＋同口径复测」成为值得立项的数据侧干预。

## 2. 核查规则（冻结清单，脚本按此实现；规则本身不在试点内修改，误报经分类环节吸收）

对每张含 `chart_lines_top_to_bottom` 的卡，按自上而下每 6 行一组（12/18 行卡为双/三卦）逐组核查。爻位自下而上编号 1–6。约定（《增删卜易》系刊印通例）：本卦侧动爻以 ○（老阳）/ㄨ 或 ×（老阴）代爻符、静爻作 ⚊/⚋；变卦侧六亲以本宫为纲。

- **R1 爻符—动变一致**：由本卦侧六爻爻符得本卦；动爻位集合＝带 ○/ㄨ/× 标记之位；变卦应＝本卦于动位翻爻。变卦侧（有右栏时）六爻爻符须与推得的变卦逐位一致。
- **R2 纳甲**：每爻地支须等于其卦（本卦侧用本卦、变卦侧用变卦）对应内/外卦纳甲序（乾 子寅辰/午申戌、坤 未巳卯/丑亥酉、震 子寅辰/午申戌、巽 丑亥酉/未巳卯、坎 寅辰午/申戌子、离 卯丑亥/酉未巳、艮 辰午申/戌子寅、兑 巳卯丑/亥酉未，自下而上）。
- **R3 五行**：地支→五行固定配（子水、丑土、寅木、卯木、辰土、巳火、午火、未土、申金、酉金、戌土、亥水），须与卡面所书一致。
- **R4 六亲**：由本卦所属宫之五行（乾金、坤土、震木、巽木、坎水、离火、艮土、兑金）与爻五行生克定（同我兄弟、我生子孙、生我父母、我克妻财、克我官鬼）；两侧同纲。
- **R5 世应**：世位由八宫世次定（本宫 6、一世 1、二世 2、三世 3、四世 4、五世 5、游魂 4、归魂 3），应位＝世位 ±3（六爻内）。卡面世/应标记：位置错误＝硬标记；应有未标＝软标记。
- **R6 动爻文本互核**：`moving_lines` 文本所载动位（初/二/三/四/五/上）与动爻六亲地支，应与卦面标记一致；文本格式不可解析者记不可核，不作标记。
- **R7 空亡互核**：卡含 `空亡` 字段且 `asked_at`/`date_ganzhi` 含日干支时，日柱所属旬之空亡（甲子旬戌亥、甲戌旬申酉、甲申旬午未、甲午旬辰巳、甲辰旬寅卯、甲寅旬子丑）须与所书一致。

无卦面卡（chart_complete＝false 等源本无全盘者）不适用 R1–R6，单列计数、不作缺陷。解析失败（格式异例）单列「不可解析」计数，不作缺陷。

## 3. 普查（脚本，全量 246）

- 脚本 `input-audit/audit_liuyao_inputs.py` 确定性运行，产出 `census.json`（逐例逐条标记）与 `CENSUS.md`（汇总：可核查卡数、各规则硬/软标记数、涉例数、不可解析与无卦面计数）。
- 普查只产标记，不产结论：标记是否属实由 §4 对源核验定。

## 4. 对源核验（数据角，独立席位）

- 样本：硬标记涉例若 ≤36 例则全验；若 >36 例，以种子 **20261030** 随机抽 36 例。另以同一种子流抽**无任何硬/软标记且含卦面**的对照例 12 例（验审计假阴性）。
- 每例核验：按卡面 provenance 所载书目/版本/出处，将卡面卦面与源本原文逐字段对读（在线本走合法在线读：维基文库等；用户到货批 PDF 仅内部研究使用、不外传）。逐标记分类：
  - **A 输入转录错误**：源本与卡面不符且源本自洽（可纠正，记纠正值与源本出处）；
  - **B 源本如此**：卡面与源本一致（源本自身不一致或编校问题），输入忠实——不纠正、只登记；
  - **C 核查误报**：约定差异或解析问题，卡面与源本均无误。
  - 对照例若查得 A 类错误，记为审计假阴性（FN），逐例登记其逃逸原因类型。
- 核验席位只对源分类，不看任何轮次分数、不作断、不评分（五角分离照旧）。核验结论以盘上文件为准。

## 5. Go / No-Go（事前写定，试点内不改）

- **GO（全量推广）**：同时满足——(i) 确认 A 类涉例数（抽样时按 A 率×硬标记涉例总数估计、且已确认 A 例数下限 ≥5）≥ **8 例**；(ii) 精确率 A/(A+C) ≥ **0.4**（按标记条数计）；(iii) 对照 FN ≤1 例（FN ≥2 先修订核查规则重跑普查一次、仅对新增标记补验，再适用本条一次；再失败即 NO-GO）；(iv) 核验总席位 ≤8（代价上限）。
- **NO-GO**：未达 GO 任一条件 → 如实登记「六爻数据侧本路不成立、六爻维持观察」，转 STAGE-SUMMARY-14 §3 的合读路径：由下一份预注册（R32 PREREG）事前声明平台 (c) 的多轮合读判据（合读池资格＝六爻输入与六爻方法均未变的轮次，逐轮核资格后入池；R31 本轮判读不因此改动），再行 R32。
- GO 之后果（本预注册一并预告，细节由 R32 PREREG 落定）：全量核验全部硬标记涉例 → 建 `inputs-dev11`（仅 A 类卡按源本纠正，逐例附出处、字节清单、泄漏扫描，inputs-dev10 原件不动）→ R32 全池正式轮，唯一变量＝inputs-dev11；主判据为 (c) 子集配对差对 R31 锚 −1.955 的改善带（事前数值在 R32 PREREG 写定）；平台 (a)(b)(c) 门槛照 R31 数值不回溯放宽。
