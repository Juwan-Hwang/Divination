# 盲测对标协议（benchmark/PROTOCOL.md）

## 总目标（2026-10-29 用户最终定调，覆盖此前一切收录口径冲突）
**唯一总目标：盲测中与大师结果尽可能一致、尽可能多地通过测试集。**
- A–E 来源分级保留，但只作**来源标注**（原典/伪托/现代建构/民间说法如实标明），不再作收录门槛。
- 现代建构/伪托只要是大师们实际奉行、按之作断的（如《梅花易数》托名邵雍而历代据以断卦、Waite 牌义本属现代建构而为塔罗标准），照常收录并作为对标依据；出处真伪照实标注，不许假装是真古籍。
- 「暂不采用清单」（MANIFEST）只留既无大师背书、又明显让结果偏离大师的条目；若迭代发现某现代说法反而提升一致性，可移回收录并在 iterations.md 记明依据——**以测试结果为准，不以出身为准**。

## 目的
**迭代目标函数只有一句话：与大师结果的差距最小化。**
不论盲测方用什么方式——任何体系、任何流派、任何组合——只要最后算出的结果和大师差不多，就是成功。通过/不通过只看最终结果与大师原断的接近程度；方法、流派、依据链一律不计入通过判定。依据链只在结果对不上时用作诊断：定位是哪一步偏了、该调哪条规则。

## 统一原则（2026-10-29 用户拍板，方法无关）
真实验证不拘泥中方/西方/单个方法：**用中国理论算出和西方大师一样的结论，同样算准。** 因此：
- 盲测方可以**任选或混用任何体系**（六爻、八字、占星、塔罗、梅花……），以问题与对象为准选法。
- 评分**只对齐三件事**：结论方向、关键具体断语、应验结果。**不考核**所用方法是否与大师同体系。
- 跨体系算出同一结论的，在评分记录中记为 **「跨体系收敛」**，是加分信号（表明结论不依赖单一体系的任意约定）。
- 数据集核心结构与此对齐：每例 = subject（被算对象基本信息 + 当时背景）+ master_predictions[]（大师、体系、时间、预测原文节录、应验结果）；盘面/卦象等体系特有数据只是可选附件。

## 角色与隔离
- **盲测方**：只能拿到 `cases/input/` 的案例卡（或 masters-dataset 的 inputs）+ 本知识库 + skill。**禁止**：看 answers、联网搜该案例。
- **评分方**（主会话或另一 agent）：盲测完成后才打开 answers，按量表打分，记录写进 `iterations.md`。

## 评审独立性修订（2026-10-29 用户确认，正式修订，覆盖上节「评分方」旧口径）
开封对照打分必须由**独立的评审方（judge）**担任，三方分工互不兼任：
- **盲测方**：只见 inputs + 知识库，负责作断。
- **评审方**：独立的全新 agent，只接收 predictions + 对应金标 answers + 本协议量表，负责开封、逐例打分和写差距点评；它不参与作断、不参与规则修改，也不知道预测出自哪一轮/哪个版本——交给它的文件须抹掉轮次与版本信息，防宽松偏袒。
- **主持方**：只负责分发、汇总评审给出的分数、做差距诊断与规则调整建议，**不得自己改分**；评审分数与主持方诊断在 REPORT 里分开呈现。
- 若某轮已出现主持方自打分，该分数作废，须按本结构重新派独立评审打分后再出 REPORT。
- **题库来源**：正式考题从 `~/workspace/divination/masters-dataset/`（inputs/answers 分离的 JSONL，专门收集流程维护）挑选；本目录 cases/ 是首批自典籍原文抽取的种子考题，待对账合并，不重复全量收集。

## 论文级方法学修订（2026-10-29 用户确认，最高优先，覆盖此前一切角色口径）
本基准按「要写论文」的学术级别严谨执行。同一轮、同一批案例内，任何 agent 不得兼任两角——「不能都一个」。

### 五角分离
1. **数据角**：只管收集/整理案例与金标封存，不作断、不评分。
2. **盲测角**：全新上下文，只见 inputs 与知识库，负责作断。
3. **评审角**：独立 agent，只见匿名化预测（抹去轮次/版本信息）+ 金标 + 量表，负责开封打分；条件允许时双评审独立打分并报告一致性，分歧例由第三个评审仲裁，仲裁过程留痕。
4. **修订角**：只依据评审给出的聚合分数与差距清单改规则，不接触单例金标原文（防按答案改规则）。
5. **主持角**：只做分发、汇总、归档与方法合规检查，不作断、不打分、不改分。

### 论文级规范
- **预注册**：每轮开跑前先在 iterations.md 写定本轮假设、样本范围、评分口径，写定后本轮内不得更改口径；口径变更只能从下一轮起并注明理由。
- **全程留痕可复现**：每轮冻结知识库/skill 的版本快照（存 benchmark/runs/roundN/kb-snapshot/ 或记哈希清单），逐例保存盲测原始输出、评审原始打分表、仲裁记录；阴性结果（分数下降、假设被否）与阳性结果同等完整报告，不许挑报。
- **统计口径**：分数一律带样本量 n；分体系分项样本过小（n<5）时标注「样本不足、仅供参考」；著名例与非著名例分开报告，以控制背题污染。
- **数据卫生**：dev/test 划分一次冻结、写入 splits.json 后不得因成绩挪动案例；test 金标只许评审角在阶段验收轮开封，且开封即留日志。

## 迭代节奏与停止标准（2026-10-29 用户确认，覆盖此前按天节奏）
- **链式连续循环**：不按天跑、不等间隔——每一轮 REPORT 落盘即立刻为下一轮写预注册并开跑，直到满足停止标准。中间轮次只留痕归档，不逐轮对外汇报；达到停止标准或硬阻塞时才出总报告。
- **停止标准**（满足才可停）：
  1. dev 总分连续两轮提升均 <1 个百分点（平台期），且各分体系（n≥5）均无 >3 个百分点的单轮波动；
  2. 触发平台期后，由评审角开封 test 留出集跑一次阶段验收：留出集总分与 dev 分数差距在 5 个百分点以内 → 视为收敛，可以停；差距明显更大（过拟合 dev）→ 以留出集暴露的问题为新一轮诊断输入，继续循环；留出集开封后即转为已用数据，在 splits 与日志中如实标注，后续验收需另设新留出或如实降级表述；
  3. 或出现硬阻塞（数据/工具不可用等），停下并如实报告卡点。
- **总报告内容**（停时出具）：总轮数、分数轨迹（每轮 dev 分数与 n）、留出集验收分、最终改了哪些规则、仍存的最大差距。

## 评分量表（结果三项，各 0–2 分；只有这三项决定通过）
1. **结论方向**：2=与大师同向同级；1=同向不同级/含糊；0=反向或不敢断。
2. **关键具体断语**：2=给出与大师同等具体程度的断语（对象/时间/部位级别）且命中；1=有具体但错位；0=只有空泛吉凶。
3. **应验结果对齐**：2=断语与实际应验事件对齐；1=部分对齐；0=不对齐。
- 合格线（暂定）：三项合计 ≥4 为通过。
- 附加记号：**跨体系收敛**（盲测方用的体系与大师不同而结果对齐）单独标注，作为置信加分，写入迭代记录，不改变三项分数。
- **依据链不计分**：只在不通过时用于诊断归因（规则缺失 / 规则冲突 / 默认约定选错 / 选法不当 / 某一步推错），定位该调哪条规则；归因后才许改规则。结果通过者，不因依据链与大师不同而扣分。

## 迭代纪律
- 每次改动写进 iterations.md：日期、案例、原分数、归因、改了哪条规则（附典籍原文回扣）、复测分数、是否跨体系收敛。
- **防过拟合**：调整必须能回扣典籍规则原文或另一成例支持；复测不得使其他案例掉分（掉分回滚并记录）。
- 流派/约定默认值（calibration.md 第三节）由算者自决、由盲测校正：自决错了算算者的账，在此修正，不推回求测者。

## 已知局限（不得隐瞒）
1. **训练语料污染**：著名成例可能已进入大模型训练语料，盲测方可能「背过答案」。缓解：优先冷门古例充实题库、定期换新题；评分以结果为准的口径下，此局限意味着「通过」证明的是结果复现能力，不单独证明推理过程。
2. **幸存者偏差**：典籍成例是编者筛选的「验例」——达标只证明断法/选法与大师一致，不证明占卜本身的预测效力。本库立场：占卜是文化与决策参考框架，不作科学效力背书。
3. **文本层累**：古例经后世编集，个别细节可能经润饰；出处栏如实标注版本与托名问题。

## 双轴评测补充协议（2026-10-29 用户拍板新增，补充评测，不改动任何既有分数）

背景：用户指出「与大师反着断、却与实际结局应验」的案例（如 AS-302、AS-305 一类）更有价值——只用「与大师一致」单轴评分，会把这类案例记为失败，也会把「复现大师之误」记为通过。本补充协议新增第二评测轴，原轴一分数一律不动，补评为追加的补充评测（append-only）。

### 双轴定义
- **轴一＝大师一致性**：预测与大师原断的接近程度，即既有量表三项分数（方向/断语/应验对齐），照引各轮 final-scores，不重评、不改动。
- **轴二＝实际应验**：预测与该案例**记录在案的客观结局**的吻合度，与大师断语对错无关。量表与轴一同构，三项各 0–2：
  1. **方向对现实**：2=预测结论方向与实际结局方向同向同级；1=同向不同级/含糊；0=与实际结局反向或不敢断。
  2. **关键断语对现实**：2=预测给出的具体断语（对象/时间/部位级别）被实际结局证实；1=有具体断语但只部分被证实或错位；0=具体断语被实际结局证伪、或只有空泛吉凶。
  3. **应期/时点对现实**：2=预测给出的应期/时点与实际发生时点对齐；1=部分对齐（尺度对、坐标偏，或只对其一）；0=不对齐。预测未给出任何应期/时点、或结局无时点可核者，本项记 1 并标注「无时点可核（中性记 1）」，不得以缺失扣至 0、也不得给 2。
- 轴二合计 ≥4 记**轴二通过**。

### 结局可得性分级（轴二的准入门槛，数据角独立执行）
轴二最大的风险是拿大师自述充当独立现实标签，故逐例先分级：
- **A 级**：结局有独立于大师断语的客观记录——史实、带时间戳的公开事件结果（选举官方结果、公开新闻记录、机构批准记录等）、或案例原文明确记载的实际结果（与断语文本可分离的具体事件记录：日期、数额、事件经过、求测者实际反馈的事件等）。**只有 A 级案例可评轴二。**
- **B 级**：结局只有大师（或编集者）自述、或纯书内结局（book_internal_only 一类），其内容与大师断语不可分离（如原注自载的命格评语本身、无独立事件记录的「果然应验」式自述）。B 级标「轴二不可评」，只统计数量，**严禁把大师自述结局当作独立现实标签打轴二分**。
- 分级须逐例给出理由并落盘；拿不准的从严归 B，并在分级表中标注「从严归 B」。

### 补评执行口径
- 范围：Round 17 的 dev 94 例预测 + Round 18 的 test 41 例预测（最终冻结规则的产物）＋ Round 1 的 dev 93 例预测作基线对照。
- 匿名化：预测交评审前抹去轮次、轴一分数与一切版本信息并打乱顺序；评审不得知道某条来自哪一轮，也不见大师断语原文（防锚定）——评审只见预测（方向＋断语＋小结）、该例的客观结局记录、轴二量表。
- 评审结构：双评审独立打分；分歧定义同前（断语＋应期两项之和两评审相差 ≥2，或轴二通过判定不一致）→ 第三个评审仲裁，仲裁分为准；非分歧例取双评审均值。
- 角色分离：数据分级、评审、仲裁、主持互不兼任；主持只分发、汇总与写报告，不打分、不改分。
- 产出：benchmark/dual-axis/DUAL-AXIS-REPORT.md，含三组轴二成绩（带可评 n 与不可评 n）、双轴四象限计数（双高／只合大师／只合现实／双低）、「超越大师例」清单（轴一 <4 而轴二 ≥4）、「复现大师之误」清单（轴一 ≥4 而轴二 <4）、结论（最终系统实际应验水平与大师一致性水平的关系，如实报告）。
- 本补充协议不改变停止标准、不重启迭代链；补评结论只作补充评测登记，后续是否据此调整目标函数须用户另行拍板。
